Verifying a Release Candidate

Guide for anyone participating in the release vote, based on ASF Release Policy.

Set Release Candidate Variables

Copy the exact values from the vote email before running any command:

RELEASE_VERSION="0.3.0"
RC_NUM="1"
RC_TAG="v${RELEASE_VERSION}-rc${RC_NUM}"
RC_COMMIT_SHA="<40-character commit from the vote email>"
RELEASE_RUN_ID="<successful Release workflow run ID>"
ARCHIVE="apache-paimon-mosaic-${RELEASE_VERSION}-src.tgz"

Validating Distributions

The release vote email includes links to:

  • Distribution archive: source tarball (apache-paimon-mosaic-${RELEASE_VERSION}-src.tgz) on dist.apache.org dev
  • Signature file: apache-paimon-mosaic-${RELEASE_VERSION}-src.tgz.asc
  • Checksum file: apache-paimon-mosaic-${RELEASE_VERSION}-src.tgz.sha512
  • KEYS file: https://downloads.apache.org/paimon/KEYS

Download the archive (.tgz), .asc, and .sha512 from the RC directory (e.g. paimon-mosaic-${RELEASE_VERSION}-rc${RC_NUM}/) and the KEYS file.

Verifying Signatures

Import the keys into your local keyring:

curl https://downloads.apache.org/paimon/KEYS -o KEYS
gpg --import KEYS

Verify the .asc file:

gpg --verify "${ARCHIVE}.asc" "${ARCHIVE}"

If verification succeeds, you will see:

gpg: Signature made ...
gpg: using RSA key ...
gpg: Good signature from "Release Manager Name (CODE SIGNING KEY) <...@apache.org>"

Verifying Checksums

On macOS (shasum):

shasum -a 512 -c "${ARCHIVE}.sha512"

On Linux (sha512sum):

sha512sum -c "${ARCHIVE}.sha512"

If successful:

apache-paimon-mosaic-${RELEASE_VERSION}-src.tgz: OK

Verifying Source, Tag, Commit, and CI Identity

Confirm that the source archive, signed RC tag, vote email, and exact successful workflow run all identify one commit:

SOURCE_COMMIT="$(gzip -dc "${ARCHIVE}" | git get-tar-commit-id)"
test "${SOURCE_COMMIT}" = "${RC_COMMIT_SHA}"

git clone --filter=blob:none --no-checkout \
  https://github.com/apache/paimon-mosaic.git paimon-mosaic-git
git -C paimon-mosaic-git fetch origin \
  "refs/tags/${RC_TAG}:refs/tags/${RC_TAG}"
git -C paimon-mosaic-git checkout --detach "${RC_TAG}"
test "$(git -C paimon-mosaic-git rev-parse HEAD)" = "${RC_COMMIT_SHA}"

python3 paimon-mosaic-git/tools/validate_release_tag.py \
  "${RC_TAG}" \
  --keys-file "$(pwd)/KEYS" \
  --repository paimon-mosaic-git \
  --expected-commit "${RC_COMMIT_SHA}"

test "$(gh run view "${RELEASE_RUN_ID}" \
  --repo apache/paimon-mosaic --json headSha --jq .headSha)" = "${RC_COMMIT_SHA}"
test "$(gh run view "${RELEASE_RUN_ID}" \
  --repo apache/paimon-mosaic --json conclusion --jq .conclusion)" = "success"
test "$(gh run view "${RELEASE_RUN_ID}" \
  --repo apache/paimon-mosaic --json workflowName --jq .workflowName)" = "Release"
test "$(gh run view "${RELEASE_RUN_ID}" \
  --repo apache/paimon-mosaic --json event --jq .event)" = "push"
test "$(gh run view "${RELEASE_RUN_ID}" \
  --repo apache/paimon-mosaic --json headBranch --jq .headBranch)" = "${RC_TAG}"

Also open the exact workflow URL from the vote email and confirm that it is the top-level Release workflow for the RC tag, not a branch dispatch or a different SHA.

Verifying Build

Extract the source release and verify it builds. You need Rust (stable toolchain). Running the release license tools also requires Python 3.11+, while the Python binding runtime supports Python 3.9+.

tar -xzf "${ARCHIVE}"
cd paimon-mosaic-${RELEASE_VERSION}

Rust

Build and test all workspace crates. The two Rust readback tests depend on files written later by Java and Python, so skip them in the initial workspace test and generate the shared Rust fixtures first:

cargo build --workspace --release --locked
cargo test --workspace --locked -- \
  --skip test_read_java_written_file \
  --skip test_read_python_written_file
cargo test --release --locked -p paimon-mosaic-core \
  --test interop_write_test

Java

Build the Java binding (requires JDK 8+ and Maven):

cargo build --release --locked -p paimon-mosaic-jni

Copy the built native library into the resource directory for the platform being verified. Run only the snippet for your current platform.

Linux x86_64:

mkdir -p java/src/main/resources/native/linux/x86_64
cp target/release/libpaimon_mosaic_jni.so \
  java/src/main/resources/native/linux/x86_64/

Linux aarch64:

mkdir -p java/src/main/resources/native/linux/aarch64
cp target/release/libpaimon_mosaic_jni.so \
  java/src/main/resources/native/linux/aarch64/

macOS aarch64:

mkdir -p java/src/main/resources/native/macos/aarch64
cp target/release/libpaimon_mosaic_jni.dylib \
  java/src/main/resources/native/macos/aarch64/

Windows x86_64:

mkdir -p java/src/main/resources/native/windows/x86_64
cp target/release/paimon_mosaic_jni.dll \
  java/src/main/resources/native/windows/x86_64/
REPO_ROOT="$(pwd)"
mvn -f java/pom.xml clean test \
  "-DargLine=-Djava.library.path=${REPO_ROOT}/target/release"
cargo test --release --locked -p paimon-mosaic-core \
  --test interop_read_test test_read_java_written_file

Python

Build and test the Python binding (requires Python 3.9+):

cargo build --release --locked -p paimon-mosaic-ffi
python3 -m pip install pyarrow pytest
MOSAIC_LIB_PATH="${PWD}/target/release" python3 -m pip install -e ./python
MOSAIC_LIB_PATH="${PWD}/target/release" python3 -m pytest -v python/tests
cargo test --release --locked -p paimon-mosaic-core \
  --test interop_read_test test_read_python_written_file

C++

Build the C++ tests (requires CMake):

cargo build --release --locked -p paimon-mosaic-ffi
cmake -S cpp -B cpp/build \
  -DMOSAIC_FFI_LIB="${PWD}/target/release/libpaimon_mosaic_ffi.so"
cmake --build cpp/build
LD_LIBRARY_PATH="${PWD}/target/release${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}" \
  cpp/build/test_mosaic

Verifying LICENSE and NOTICE

Verify that:

  1. The LICENSE and NOTICE files exist in the root directory and are correct.
  2. All source files have ASF license headers.
  3. All dependencies have licenses compatible with ASL 2.0 (ASF third-party license policy).
  4. Cargo.lock, dependency manifests, and target-specific binary legal reports are present and current.
  5. No unexpected files are included (.git, .github, .asf.yaml, .gitignore, .idea, target/ should all be excluded).
cargo install cargo-deny --version 0.19.0 --locked
cargo install cargo-about --version 0.9.1 --locked
cargo fetch --locked
python3 tools/dependencies.py check
python3 tools/generate_license_reports.py --check

Testing Published Artifacts

Rust (crates.io)

RC tags do not publish to crates.io (dry-run only). You can test the Rust crate from the source tarball or via git tag dependency:

[dependencies]
paimon-mosaic-core = { git = "https://github.com/apache/paimon-mosaic", tag = "v${RELEASE_VERSION}-rc${RC_NUM}" }

Java (Apache Nexus Staging)

The Release Manager signs and stages Java artifacts locally from the native inputs exported by the exact successful RC workflow run. To test:

  1. Find the staging repository at repository.apache.org.
  2. Add the staging repository URL to your pom.xml: 
    <repositories>
  <repository>
    <id>apache-staging</id>
    <url>https://repository.apache.org/content/repositories/orgapachepaimon-XXXX/</url>
  </repository>
</repositories>
  3. Add the dependency: 
    <dependency>
  <groupId>org.apache.paimon</groupId>
  <artifactId>mosaic</artifactId>
  <version>${RELEASE_VERSION}</version>
</dependency>
  4. Verify the JAR contains native libraries for all 4 platforms:
    • native/linux/x86_64/libpaimon_mosaic_jni.so
    • native/linux/aarch64/libpaimon_mosaic_jni.so
    • native/macos/aarch64/libpaimon_mosaic_jni.dylib
    • native/windows/x86_64/paimon_mosaic_jni.dll

Python (TestPyPI)

The RC tag publishes wheels to TestPyPI after the Rust and Java release jobs succeed. Install and verify:

python3 -m pip install pyarrow
python3 -m pip install --no-deps \
  --index-url https://test.pypi.org/simple/ \
  paimon-mosaic==${RELEASE_VERSION}rc${RC_NUM}
python -c "import mosaic; print('OK')"

Verify wheels are available for: Linux x86_64, Linux aarch64, macOS aarch64, Windows x86_64.

Voting

Votes are cast by replying to the vote email on the dev mailing list with +1, 0, or -1.

State whether your vote is binding or non-binding. Only PMC members have formally binding votes. See Apache Foundation Voting.

A release vote remains open for at least 72 hours and passes only with at least three binding +1 votes and more binding +1 than binding -1 votes.

Include a short list of what you verified. This helps the community see what has been checked.

Checklist you can reference in your vote:

  • Validating distributions
  • Verifying signatures
  • Verifying checksums
  • Verifying build
  • Verifying LICENSE and NOTICE
  • Testing published artifacts
